# 语音转文字 / 文件解析

机器人现在能"听"语音、"读"文件了。两者都是**先把内容转成文字，再进对话上下文**，所以人设、记忆、回复逻辑不用改。

---

## 一、语音转文字

### 流程

```
群里的语音消息（微信 SILK 格式，3~60 秒）
   │
   ├─ wechatauto 从微信库里取出 .silk（本机文件，不上传）
   ├─ pilk 解码 SILK → 24kHz WAV（纯 Python，不需要 ffmpeg）
   ├─ numpy 重采样到 16kHz 单声道（绕过 PyAV 的版本兼容坑）
   ▼
faster-whisper（本地 CPU，int8）
   ▼
"[语音] 表面怎么处理啊"   ← 进上下文
   ▼
大肥鱼照着人设回话
```

### 实测

```
语音 3.32 秒 → 识别 3.1 秒 → "表面怎么处理啊"
```

### 配置

```yaml
asr:
  enabled: true
  model: "base"        # tiny / base / small / medium；越大约准越慢
  language: "zh"
  device: "cpu"        # 有 NVIDIA 显卡可改 cuda（需装对应 ctranslate2）
  compute_type: "int8"
  models_dir: "data/models"
  max_seconds: 120     # 超过 2 分钟的语音不识别
```

- **首次启动会自动下载模型**（base 约 145MB）到 `data/models`，之后离线可用；
- 语音**不上传任何服务器**，纯本地识别；
- 想更准：`model: "small"`（约 460MB，识别慢 1~2 秒），实测同一段语音 base 和 small 结果一致，日常建议 base；
- 识别失败/关闭时显示 `[语音]` 占位符，不影响其他消息。

## 二、文件解析

### 支持的格式

| 类型 | 处理方式 |
| --- | --- |
| 文本类：txt / md / csv / json / log / 代码（py/js/ts/…） | 读前 2000 字进上下文 |
| Word `.docx` | 提取段落 + 前 3 张表格 |
| Excel `.xlsx` | 读前 2 个工作表、每个前 10 行 |
| PDF `.pdf` | 有文字层就提取前 5 页 |
| 其它二进制 / 大于 20MB | 只告诉模型「文件名 + 大小」，不硬读 |

> PDF 需要 `pypdf`（requirements 已包含）；扫描件 PDF 没有文字层，会提示解析不到文字。

### 效果示例

```
[文件] 会议纪要.txt（2.1 KB）：周三下午三点开会，预算 3000，下周三交方案……
```

### 配置

```yaml
files:
  enabled: true
  max_text_chars: 2000   # 每个文件最多读多少字（防止把上下文撑爆）
  max_file_mb: 20        # 超过这个大小只报文件名
  dir: "data/media/files"
```

文件会下载到 `data/media/files/` 再解析。

## 五、已知限制

- 语音识别质量取决于模型和录音质量，方言/嘈杂环境会不准；建议把原话连同识别结果一起理解，不要当逐字稿；
- 长语音（>2 分钟）会跳过，避免占用识别时间；
- 加密 PDF、扫描件、超大文件不解析；
- 语音/文件解析会**短暂阻塞轮询**（识别一条语音约 1~3 秒），群消息密集时略有延迟。
